# 해설 작성·검수 가이드

문항 하나 = `content/problems/<학년도>-<시험>-math-<번호>.yaml` 파일 하나. 새 초안은 `npm run new -- 2027 22`.

## 필드별 원칙

| 필드 | 원칙 |
| - | - |
| `hint` | 정답, 핵심 식, 최종 경우의 수를 드러내지 않는다. "어떤 조건을 먼저 볼지"만 말한다. 학생이 이것만 보고 다시 풀 수 있어야 한다. |
| `firstIdea` | 첫 식을 **왜** 이렇게 세우는지. 문제의 어떤 조건이 이 출발을 가리키는지 한두 문장. 모든 해설에서 같은 위치(풀이 맨 위)에 보인다. |
| `steps[].body` | 그 단계의 계산·판단. 한 단계에 한 가지 생각. |
| `steps[].why` | 그 식이나 판단이 나오는 이유. "계산하면"으로 넘어가지 않는다. |
| `pitfalls` | 실제로 자주 틀리는 지점: 조건 누락, 경우 빠뜨림, 부호·범위 실수, 그래프 오독. 일반론("계산 실수 주의")은 쓰지 않는다. |
| `related` | 개념이 **실제로** 이어지는 문항만. 같은 단원이라는 이유만으로 넣지 않는다. 공개되지 않은 문항은 자동으로 숨겨진다. |
| `concepts` | `course2015`(출제 당시 과목)와 `course2022`(2028 수능 과목)를 함께 적는다. |

## 문제 본문 (`problem`)

문항 페이지 맨 위에 문제를 **텍스트·수식으로 다시 입력해** 보여준다. 캡처 이미지는 쓰지 않는다(흐리고, 검색·확대가 안 된다).

- 원문 문구·기호·배점을 **그대로** 옮긴다. 줄바꿈 위치만 화면 폭에 맞게 달라도 된다.
- 화면 순서: `body` → `figure` → `conditions`(테두리 상자) → `after` → `choices`(①~⑤).
- 조건 상자 항목은 `(가) ...` 로 시작한다. 라벨이 자동으로 내어쓰기된다.
- 선택형은 `choices` 5개 필수. `answer.choice` 번 선택지와 `answer.value`가 다르면 공개가 막힌다.
- 휴대전화 폭(375px)에서 긴 별도 줄 수식은 `aligned`로 나눈다.

**그림**: 그래프·도형은 `src/figures/<id>.svg`로 다시 그리고 `figure: <id>`로 연결한다. 선·글자는 `currentColor`, 빈 점의 채움은 `var(--fig-bg)`로 두면 다크 모드에서도 보인다. 가능하면 문제 조건을 만족하는 실제 함수로 그린다(14번은 $a^6=\frac72$ 로 그림).

**원문 대조**: `paperPage`와 `paperCrop: [x0, y0, x1, y1]`(쪽 대비 비율, 왼쪽 위가 0)을 적고 `npm run crop` → `.cache/crops/<id>.png`. 옮겨 적은 내용을 이 이미지와 한 글자씩 대조한다(이미지는 화면에 쓰지 않는다). 문제지는 2단이라 왼쪽 단은 대략 x `0.099~0.492`, 오른쪽 단은 `0.513~0.902`.

해설(`hint`, `steps` 등)에는 문제 문구를 다시 길게 옮기지 않고 "조건 (가)에서"처럼 가리킨다.

## 수식

- 인라인 `$...$`, 별도 줄 `$$...$$` (KaTeX 문법).
- 백슬래시가 들어가는 글은 YAML `|` 블록으로 쓴다. 따옴표 문자열 안에서는 `\\frac`처럼 두 번 써야 한다.
- 수식 문법 오류는 빌드를 실패시킨다.

## 발행 흐름

초안 → 정답 대조 → 풀이 검수 → 모바일 미리보기 → 공개

1. **초안**: `status: draft`. `npm run dev` 로 휴대전화 폭에서 보면서 작성한다.
2. **정답 대조**: 옮겨 적은 문제 본문이 원문과 같은지(`.cache/crops/`)도 함께 확인한다. 공식 정답표의 값과 선택지 번호를 대조한다. 홀·짝수형 선택지 번호가 다르면 `paperType`과 `choiceOtherPaper`를 채운다. 도구로 재계산할 수 있으면 교차 확인한다. → `reviews`에 `answer-check`
3. **풀이 검수**: 작성과 분리된 절차로 조건 적용, 경우 누락, 수식 변형을 따로 확인한다(`docs/review-sheet.md`). → `solution-review`
4. **고난도**(`difficulty: hard`)나 풀이가 애매한 문항: 해설을 보지 않은 새 맥락에서 다시 풀어 답을 확인한다. → `independent-resolve`
5. **모바일 미리보기**: 375px 폭에서 수식 줄바꿈, 가로 스크롤, 그림·상자, 접기·펼치기를 확인한다. → `mobile-preview`
6. **공개**: `status: published`, `changelog`에 "최초 공개". 조건이 하나라도 빠지면 `npm run build`가 실패하고 빠진 항목을 알려준다.

미리보기 화면 상단의 **"공개 전 확인할 항목"** 배너에 남은 단계가 표시된다.

## 공개 후 오류

정답이나 핵심 논리 오류가 확인되면:

1. 즉시 `status: withdrawn` 으로 바꾸고 배포한다. 공유된 주소는 "수정 중" 안내로 남고(noindex, 광고 없음), 목록·검색·사이트맵에서 빠진다.
2. 수정본을 다시 정답 대조·풀이 검수한다(`reviews`에 새 기록 추가).
3. `status: published`, `changelog`에 수정 내용을 적고 배포한다.

## 작업 시간 기록

`minutes: { writing, review }`는 사람이 직접 작성·검수한 시간(분)만 적는다. Claude가 한 작업은 기록하지 않는다.
