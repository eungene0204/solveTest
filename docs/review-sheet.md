# 파일럿 8문항 검수표

정답 대조(`answer-check`)는 끝났다. 남은 것은 사람이 해야 하는 검수다.
`npm run dev` → http://localhost:3000/suneung/2027/math/ 에서 문항별로 진행한다.
**시작·끝 시각을 적어 검수 시간(분)을 잰다** — 66문항 소요 산정에 쓴다.

## 1. 풀이 검수 (`solution-review`) — 8문항 전부

해설을 처음부터 따라가며 확인한다.

- [ ] **문제 본문이 원문과 같은가** — 숫자·부호·첨자·배점까지. `npm run crop` 후 `.cache/crops/<id>.png` 또는 공식 문제지와 대조 (4·14번은 그림도)
- [ ] 힌트가 정답·핵심 식을 드러내지 않는가
- [ ] "왜 이렇게 시작하나"가 문제의 어떤 조건에서 나오는지 말해 주는가
- [ ] 각 단계의 "이렇게 하는 이유"가 "계산하면"으로 넘어가지 않는가
- [ ] 조건 누락·경우 빠뜨림·부호/범위 실수가 없는가
- [ ] 자주 틀리는 지점이 실제로 학생이 틀리는 지점인가
- [ ] 어색한 문장, 고등학생이 모를 용어

## 2. 독립 재풀이 (`independent-resolve`) — 15, 21, 22번

해설을 **보지 않은** 사람(본인이 해설을 이미 봤다면 다른 사람)이 문제 이미지만 보고 풀어 답을 확인한다.

| 번호 | 정답 | 재풀이한 사람 | 답 일치 | 걸린 시간 |
| - | - | - | - | - |
| 15 | 8 | | | |
| 21 | 135 | | | |
| 22 | 98 | | | |

## 3. 모바일 미리보기 (`mobile-preview`) — 8문항 전부

실제 휴대전화에서 확인한다(같은 와이파이에서 `npm run dev` 후 표시되는 Network 주소로 접속).

- [ ] 문제 이미지가 잘리지 않고 글자가 읽히는가
- [ ] 수식이 화면 밖으로 넘치거나 가로 스크롤이 생기지 않는가
- [ ] 힌트·풀이·정답 접기/펼치기가 잘 되는가
- [ ] 단계 이동 링크(1단계, 2단계…)가 맞는 위치로 가는가

## 4. 기록하는 법

문항 YAML(`content/problems/2027-suneung-math-<번호>.yaml`)의 `reviews`에 줄을 추가하고, 검수 시간을 `minutes.review`에 적는다.

```yaml
reviews:
  - step: answer-check        # 이미 있음
    ...
  - step: solution-review
    by: 홍길동
    date: 2026-11-28
    note: 3단계 문장 수정
  - step: mobile-preview
    by: 홍길동
    date: 2026-11-28
minutes:
  review: 15
```

검수 기록이 다 채워진 문항은 미리보기 상단 "공개 전 확인할 항목"이 0건이 된다. 그다음 `status: published`, `changelog`에 `{ date: 2026-11-28, note: 최초 공개 }`를 적으면 공개 대상이 된다.
단, **문항 공개 자체는 2025·2026 회차와 상관없지만, 12월 1일 확정 정답 재확인 후에 하는 것을 권한다.**

## 문제를 발견하면

해설을 직접 고쳐도 되고, 번호와 내용을 적어 Claude에게 넘겨도 된다. 정답이 다르면 즉시 알려줄 것.
