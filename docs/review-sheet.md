# 검수 절차

`answer-check`(공식 정답표 대조) 다음에 하는 세 검수 단계의 기준. 수행 주체와 그 이유는 ADR 0006.
한 문항의 검수는 아래 항목을 **전부** 확인하고, 발견한 문제를 고친 뒤에 기록한다.

## 1. 풀이 검수 (`solution-review`) — 모든 문항

작성할 때의 풀이를 믿지 않고, 원문과 해설을 처음부터 대조한다.

- [ ] **문제 본문이 원문과 같은가**: 숫자, 부호, 첨자, 부등호의 등호, 단서 문장, 배점, 선택지 순서까지 확인한다. `npm run crop`으로 만든 `.cache/crops/<id>.png`와 한 줄씩 대조하고, 그림이 있으면 SVG의 점·라벨·색칠 영역도 대조한다.
- [ ] 힌트가 정답이나 핵심 식을 드러내지 않는가
- [ ] "왜 이렇게 시작하나"가 문제의 어떤 조건에서 나오는지 말해 주는가
- [ ] 각 단계의 식 변형이 맞는가. 계산할 수 있는 값은 코드로 다시 계산한다.
- [ ] 조건 누락, 경우 빠뜨림, 부호·범위 실수가 없는가. 경우를 나눈 문항은 나눈 경우가 전체를 덮는지 확인한다.
- [ ] 각 단계의 "이렇게 하는 이유"가 "계산하면"으로 넘어가지 않는가
- [ ] 자주 틀리는 지점이 그 문항에서 실제로 생기는 실수인가 (선택지에 있는 오답과 연결되면 더 좋다)
- [ ] 고등학생이 모를 용어나 어색한 문장이 없는가
- [ ] 개념 태그의 과목명(2015·2022)과 관련 문항 id가 맞는가

## 2. 독립 재풀이 (`independent-resolve`) — 고난도와 풀이가 애매한 문항

해설을 보지 않은 새 맥락에서 문제 본문(또는 원문 이미지)만 보고 다시 풀어 정답을 확인한다. 작성한 풀이를 되읽는 것은 인정하지 않는다. 답이 같아도 풀이 경로가 해설과 다르면, 해설이 빠뜨린 경우나 더 짧은 길이 없는지 비교한다.

## 3. 모바일 미리보기 (`mobile-preview`) — 모든 문항

`npm run build:preview` 후 375px 폭에서 확인한다.

- [ ] 가로 넘침이 없다. `.katex-display`, 그림, 상자, 선택지의 `scrollWidth`를 자동 검사하고, 넘치면 `aligned`로 나눈다.
- [ ] 화면 캡처를 보고 그림의 라벨이 선과 겹치지 않는지, 상자와 빈칸이 원문 구조와 같은지 확인한다.
- [ ] 힌트·풀이·정답 접기/펼치기와 단계 이동 링크가 동작한다.

## 기록하는 법

```yaml
reviews:
  - step: solution-review
    by: Claude
    date: 2026-11-28
    note: 원문 대조 일치. 3단계 부호 설명 보강
  - step: independent-resolve
    by: Claude
    date: 2026-11-28
    note: 해설 미참조 새 맥락에서 재풀이, 답 65 일치
  - step: mobile-preview
    by: Claude
    date: 2026-11-28
    note: 375px 헤드리스 검사 넘침 없음, 캡처 확인
```

해설을 고쳤으면 `changelog`가 아니라 `reviews`의 `note`에 적는다(`changelog`는 공개 후 변경 기록). 기록이 다 채워진 문항은 미리보기 상단 "공개 전 확인할 항목"이 0건이 된다. 그다음 `status: published`, `changelog`에 `{ date: …, note: 최초 공개 }`를 적으면 공개 대상이 된다. 2027학년도는 12월 1일 확정 정답 재확인 후 공개한다.

정답이 공식 정답표와 다르다고 판단되면 즉시 사용자에게 알린다.
